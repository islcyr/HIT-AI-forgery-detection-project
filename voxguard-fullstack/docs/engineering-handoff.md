# 前后端工程交付与接入边界

## 交付目标

接收方取得工程后，可以直接启动模拟联调服务；提供符合统一入口的模型源码、匹配权重与配置后，可以运行上传、推理、结果展示和定位试听的完整流程。模型特有的网络结构、预处理、输出含义和时间映射由模型提供方确定。

模型输出可能需要适配器，不能保证任意模型源码及权重无需适配即可运行。本次补充可执行的通用输出适配示例及[完整操作说明](model-adapter-walkthrough.md)。前端、后端业务代码和接口 v0.2 均保持上一交付版本不变；新增内容集中在模型适配示例、测试和使用文档。

## 与原前端的差异

| 范围 | 修正后的行为 |
| --- | --- |
| 模型发现 | 读取 `/api/v1/models`，展示可执行模型、模拟标识和能力 |
| 上传 | 提交 `file`、`model_id`、`mode`，不重复自动重传 |
| 任务 | 接收 202，按任务 ID 查询 queued/running/succeeded/failed |
| 分数 | 保留有限实数，使用后端判断和阈值，移除百分比与前端自定判定阈值 |
| 定位 | 使用服务端区间；区分定位完成、未请求及不支持 |
| 播放 | 成功后读取后端 WAV 预览，保持原始音频时间轴 |
| 来源 | 历史及报告保留任务 ID、模型版本、模拟标识及完整结果 |
| 停止 | 停止等待只影响当前浏览器，不承诺终止服务端推理 |
| 格式限制 | 使用服务与模型的输入限制交集 |

HTML、CSS 和基础交互沿用原有工程；服务统一提供页面和 API。原 `server.cjs` 不再作为检测服务入口。

## 接口版本

随包 OpenAPI 为 0.2.0，基础地址仍为 `/api/v1`。与前一版接口资料相比，仅在模型目录项中增加必填 `is_mock`，以区分“可执行的模拟适配器”和“可执行的真实模型”。任务响应本来已有 `is_mock`，现将模型选择阶段也纳入明确标识。

`ready` 只表示该适配器在当前环境可执行，不表示准确率已经验证。`is_mock=true` 的输出必须显示模拟说明，不能改写为真实检测结论。

## 模型提供方最少交付内容

1. 网络构造源码、准确的依赖说明和匹配的 state_dict 权重。
2. 模型输入采样率、声道处理、幅度范围、输入张量形状及有效时长。
3. 整段分数的输出字段、类别方向和固定阈值。
4. 定位模型的逐帧或窗口分数、原始时间映射和固定定位阈值。
5. 模型版本、权重 SHA-256、阈值与后处理版本，以及一条参考推理输出。

通用 PyTorch 适配器支持的张量输出可以通过配置直接接入；不符合配置式入口的模型使用自定义适配器模板。缺少推理语义时，不能仅凭 `.pth` 或 `.pt` 文件推断可靠的真假和定位结果。

## 运行实现

服务采用 FastAPI，任务记录和音频存放在配置的数据目录。任务在独立子进程内解码、推理并校验结果，超时可以终止该子进程；默认串行执行。启动时对遗留未完成任务标记失败，已完成记录可以恢复查询。

模型输出在服务端校验，包括数值有限性、分数方向、阈值与判定一致性、片段顺序、时间边界、定位能力、时间序列覆盖及片段加权分数。错误不会被转换为零分、真实标签或无可疑片段。

工程面向内部基础演示。任务存储不支持多个服务进程同时写入，因此启动保持单 worker。每次任务单独加载模型，适合验证完整流程；需要高吞吐或大量并发时，再增加常驻模型进程、共享队列及权限控制。
